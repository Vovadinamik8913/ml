## Шаг 1: Объединение признаков (Wide Features)

### 📖 Простыми словами
У нас есть две таблицы с данными о клиентах:
- **Основная** — 200 признаков (базовая информация)
- **Дополнительная** — 2200+ признаков (детализированная информация)

Мы берём обе таблицы и склеиваем их горизонтально (по строкам клиентов). Получается одна большая таблица с ~2440 признаками для каждого из 750 000 клиентов.

**Аналогия:** Представьте, что у вас есть досье на сотрудника: одна папка с основной информацией (ФИО, должность, оклад), другая — с детальной (проекты, навыки, курсы). Чтобы получить полную картину, вы складываете обе папки вместе.

---

### 🔬 С точки зрения ML/математики

**Формально:**
```
X_main ∈ ℝ^(n × 200), X_extra ∈ ℝ^(n × 2240)
X_wide = [X_main || X_extra] ∈ ℝ^(n × 2440)
```
где `n = 750 000` — количество клиентов, `||` — конкатенация по оси признаков.

**Зачем это нужно:**

1. **Максимизация информационной ёмкости:** Каждый признак несёт потенциально полезную информацию о целевой переменной. В задачах с разреженными данными (много признаков, мало сигнала) важно сохранить максимум информации на входе.

2. **Снижение риска пропуска важных фич:** Некоторые признаки из дополнительного набора могут иметь высокую предсказательную силу для определённых таргетов. Отказ от них на старте — потеря потенциального качества.

3. **Последующий отбор:** Мы не используем все 2440 признаков напрямую. На следующем шаге для каждого таргета отбираются только 400 наиболее важных. Это двухэтапный подход:
   - Шаг 1: собрать всё (recall > precision)
   - Шаг 2: отобрать лучшее (precision > recall)

**Риски:**
- Проклятие размерности (curse of dimensionality)
- Шумовые признаки могут ухудшить качество
- Вычислительная сложность

**Как решаем:** Персонализированный отбор признаков для каждого таргета (см. Шаг 3).

## Шаг 2: Feature Engineering — агрегаты по строке

### 📖 Простыми словами

Для каждого клиента считаем 4 новых признака на основе всех числовых данных:

| Признак | Что означает |
|---------|--------------|
| `num_not_null_count` | Сколько у клиента заполненных полей (активность) |
| `num_row_mean` | Среднее значение по всем числам |
| `num_row_max` | Максимальное значение |
| `num_row_min` | Минимальное значение |

**Аналогия:** Если признаки — это оценки студента по предметам, то:
- `not_null_count` — сколько предметов он сдал (не прогулял)
- `mean` — его средний балл
- `max` — лучший предмет
- `min` — худший предмет

Эти 4 признака говорят об **общем паттерне поведения**, а не о конкретных значениях.

---

### 🔬 С точки зрения ML/математики

**Формально:**
```
Для строки x_i = [x_i1, x_i2, ..., x_id] ∈ ℝ^d:

f₁(x_i) = Σⱼ 𝟙[x_ij ≠ NULL]           # количество не-пропусков
f₂(x_i) = (1/|valid|) × Σⱼ x_ij       # среднее (по не-пропускам)
f₃(x_i) = maxⱼ(x_ij)                  # максимум
f₄(x_i) = minⱼ(x_ij)                  # минимум
```

**Зачем это нужно:**

1. **Признаки активности (feature density):** `num_not_null_count` — мощный индикатор. Клиент с 200 заполненными полями отличается от клиента с 50 заполненными полями. В банковских данных это коррелирует с:
   - Длительностью обслуживания
   - Количеством продуктов
   - Уровнем вовлечённости

2. **Статистические моменты (statistical moments):** 
   - Mean — первый момент, центральная тенденция
   - Max/Min — экстремальные значения, могут указывать на выбросы или специфическое поведение

3. **Инвариантность к масштабу:** Эти признаки работают как нормализующие — они дают модели якоря для сравнения клиентов независимо от абсолютных значений признаков.

4. **Борьба с разреженностью:** В данных много пропусков. Количество заполненных полей — это мета-признак о качестве данных для каждой строки.

**Почему именно эти 4:**
- Вычислительно дёшево (O(n × d), один проход)
- Интерпретируемо
- Не требуют настройки гиперпараметров
- Работают для любых числовых данных

**Почему не std/median:**
- `std` — чувствителен к выбросам, требует больше вычислений
- `median` — требует сортировки O(d log d)
- В Polars `mean/min/max` — оптимизированные SIMD-операции

## Шаг 3: Персонализированный отбор признаков (Target-wise Feature Selection)

### 📖 Простыми словами

**Проблема:** У нас 41 продукт (таргет) для предсказания. Но все они разные!

Пример:
- **Кредитная карта** зависит от: кредитной истории, доходов, трат
- **Депозит** зависит от: накоплений, возраста, стабильности дохода
- **Инвестиции** зависят от: риска, финансовой грамотности, капитала

Если использовать **одни и те же признаки** для всех 41 продукта — мы потеряем точность.

**Решение:** Для каждого продукта отбираем **свои 400 лучших признаков**.

**Как отбираем:**
1. Берём все данные по этому продукту (кто купил = 1, кто нет = 0)
2. Если продукт редкий (например, 1% клиентов) — делаем сбалансированную выборку (50% купили, 50% нет)
3. Обучаем быстрый LightGBM (150 деревьев)
4. Смотрим, какие признаки модель считает важными
5. Запоминаем топ-400 признаков для этого продукта

**Аналогия:** Врач не использует один набор анализов для всех болезней. Для сердца — ЭКГ, для желудка — гастроскопия, для лёгких — рентген. Каждый диагноз — свой набор тестов.

---

### 🔬 С точки зрения ML/математики

**Формально:**
```
Для каждого таргета t ∈ {1, ..., 41}:

1. Балансировка классов:
   - P = {i : y_i^(t) = 1}  # положительные примеры
   - N = {i : y_i^(t) = 0}  # отрицательные примеры
   
   Если |P| < K/2:
       S = P ∪ random_sample(N, K - |P|)  # все positive + досэмплим negative
   Иначе:
       S = random_sample(P, K/2) ∪ random_sample(N, K/2)  # 50/50
   
   где K = 200 000 — размер подвыборки

2. Обучение модели отбора:
   M_t = LGBM(n_estimators=150, lr=0.1, num_leaves=31)
   M_t.fit(X_S, y_S^(t))

3. Отбор по важности:
   importance_j = Σ_{деревья} gain(j)  # суммарный прирост от признака j
   Features_t = top_k(importance, k=400)

4. Кэширование:
   save(Features_t, f"data/selected_features/target_{t}.npy")
```

**Зачем это нужно:**

1. **Проклятие размерности (Curse of Dimensionality):**
   - 2440 признаков при 750k примерах — это много шума
   - Отношение сигнал/шум падает с ростом размерности
   - Сокращение до 400 признаков улучшает обобщающую способность

2. **Разные распределения для разных таргетов:**
   ```
   P(X | y^(1)=1) ≠ P(X | y^(2)=1) ≠ ... ≠ P(X | y^(41)=1)
   ```
   Каждый таргет имеет свою условную распределённость признаков. Общие признаки для всех — потеря информации.

3. **Балансировка классов (Class Imbalance):**
   - Некоторые таргеты имеют < 0.1% положительных (например, 83 положительных на 750k)
   - Без балансировки модель научится всегда предсказывать 0 и получит 99.9% accuracy, но 0% recall
   - Сбалансированная подвыборка 50/50 заставляет модель учиться различать классы

4. **Важность признаков (Feature Importance):**
   - LightGBM вычисляет важность как суммарный прирост (gain) от расщеплений по признаку
   - Это более стабильная метрика, чем permutation importance
   - 150 деревьев достаточно для оценки важности, но не для переобучения

5. **Вычислительная эффективность:**
   - Обучение на 200k вместо 750k — в 3-4 раза быстрее
   - 400 признаков вместо 2440 — в 6 раз меньше памяти
   - Кэширование позволяет не пересчитывать при каждом запуске

**Почему LightGBM для отбора:**
- Быстрее CatBoost (особенно с GPU)
- Важность признаков хорошо коррелирует с реальной предсказательной силой
- Не требует глубокой настройки для задачи отбора

**Почему 400 признаков:**
- Эмпирически: меньше 300 — теряется сигнал, больше 500 — добавляется шум
- Компромисс между bias и variance
- Достаточно для захвата паттернов, но не для переобучения

## Шаг 4: Ансамбль из 4 моделей LightGBM

### 📖 Простыми словами

**Идея:** Одна модель — хорошо, четыре — лучше!

Мы обучаем **4 разные модели** для каждого из 41 продукта. Каждая модель — как эксперт со своим "почерком":

| Модель | Характеристика | Аналогия |
|--------|---------------|----------|
| **LGB-1 (Fast)** | Быстрая, поверхностная | Студент, который быстро схватывает главное |
| **LGB-2 (Medium)** | Сбалансированная | Опытный специалист, не спешит, но и не копает слишком глубоко |
| **LGB-3 (Slow)** | Медленная, глубокая | Профессор, который изучает каждую деталь |
| **LGB-4 (FM)** | Промежуточная | Универсальный солдат |

**Как обучаем:**
- Для каждой модели используем **3-fold кросс-валидацию**
- Данные делим на 3 части: 2 обучаем, 1 проверяем (и так 3 раза)
- Итоговое предсказание — среднее по 3 фолдам

**Аналогия:** Представьте, что 4 эксперта независимо оценивают один и тот же проект. Один смотрит быстро, другой вникает глубже, третий ищет детали, четвёртый — балансирует. Итоговая оценка — среднее всех четырёх. Так мы уменьшаем риск ошибки одного эксперта.

---

### 🔬 С точки зрения ML/математики

**Формально:**
```
Для каждой модели m ∈ {1, 2, 3, 4} с гиперпараметрами θ_m:

1. K-Fold Cross-Validation (K=3):
   Разбиваем данные на K фолдов: D = {F₁, F₂, F₃}
   
   Для каждого фолда k:
       Train_k = D \ F_k           # данные для обучения
       Val_k = F_k                 # данные для валидации
       
       M_m,k = LGBM(θ_m)
       M_m,k.fit(Train_k, early_stopping=50)
       
       OOF_m[Val_k] = M_m,k.predict(Val_k)  # out-of-fold предсказания
       Pred_m,k_test = M_m,k.predict(X_test)

2. Усреднение по фолдам:
   Pred_m_test = (1/K) × Σₖ Pred_m,k_test

3. Итог для модели m:
   - OOF_m ∈ ℝ^(n_train × 41)  # предсказания на train (для валидации)
   - Pred_m_test ∈ ℝ^(n_test × 41)  # предсказания на test

Гиперпараметры моделей:
┌─────────┬──────────────┬──────────┬────────────┬─────────────┬────────────┐
│ Модель  │ n_estimators │ lr       │ num_leaves │ min_samples │ subsample  │
├─────────┼──────────────┼──────────┼────────────┼─────────────┼────────────┤
│ LGB-1   │ 300          │ 0.1      │ 31         │ 50          │ 0.8        │
│ LGB-2   │ 800          │ 0.05     │ 63         │ 30          │ 0.75       │
│ LGB-3   │ 1500         │ 0.03     │ 127        │ 20          │ 0.7        │
│ LGB-4   │ 500          │ 0.07     │ 45         │ 20          │ 0.75       │
└─────────┴──────────────┴──────────┴────────────┴─────────────┴────────────┘
```

**Зачем это нужно:**

1. **Bias-Variance Tradeoff:**
   - **LGB-1 (Fast):** Высокий bias, низкая variance — быстро обучается, но может недообучаться
   - **LGB-3 (Slow):** Низкий bias, высокая variance — глубоко обучается, но рискует переобучиться
   - **Ансамбль:** Усреднение снижает variance без увеличения bias

2. **Разнообразие моделей (Model Diversity):**
   - Разные гиперпараметры → разные границы решений
   - Ошибки моделей не коррелируют на 100%
   - Усреднение некоррелированных ошибок даёт выигрыш

   ```
   Var(Σ w_i × M_i) = Σ w_i² × Var(M_i) + Σᵢ≠ⱼ w_i w_j × Cov(M_i, M_j)
   
   Если Cov(M_i, M_j) < Var(M_i) → ансамбль лучше любой отдельной модели
   ```

3. **Кросс-валидация (3-fold):**
   - **OOF (Out-of-Fold) предсказания:** Каждый пример получает предсказание от модели, которая его не видела
   - **Честная оценка:** OOF AUC — несмещённая оценка качества на новых данных
   - **Защита от переобучения:** Модель не видит тестовый фолд во время обучения

4. **Early Stopping (50 раундов):**
   - Останавливаем обучение, если 50 итераций нет улучшения на валидации
   - Предотвращает переобучение
   - Экономит время (не нужно обучать все 1500 деревьев, если сошлось на 800)

5. **Почему именно такие гиперпараметры:**

   | Параметр | Влияние | LGB-1 | LGB-3 |
   |----------|---------|-------|-------|
   | `n_estimators` | Сколько деревьев | 300 | 1500 |
   | `learning_rate` | Шаг градиента | 0.1 (быстро) | 0.03 (медленно) |
   | `num_leaves` | Глубина деревьев | 31 (мелко) | 127 (глубоко) |
   | `min_child_samples` | Мин. примеров в листе | 50 (консервативно) | 20 (агрессивно) |
   | `subsample` | Доля данных на дерево | 0.8 | 0.7 |

   **Комбинация даёт:**
   - LGB-1: Быстрая сходимость, грубые паттерны
   - LGB-3: Медленная сходимость, тонкие паттерны
   - LGB-2, LGB-4: Промежуточные режимы

**Почему 4 модели, а не 10:**
- Закон убывающей отдачи: 5-я модель даёт +0.001 AUC, но стоит 25% времени
- 4 модели — компромисс между качеством и временем обучения
- Разнообразие уже достаточное для снижения variance

## Шаг 5: Взвешенное усреднение предсказаний (Weighted Blending)

### 📖 Простыми словами

У нас есть 4 предсказания для каждого клиента и продукта. Как их объединить?

**Вариант 1: Простое среднее**
```
Итог = (Предсказание_1 + Предсказание_2 + Предсказание_3 + Предсказание_4) / 4
```
Все модели равны, каждая имеет вес 25%.

**Вариант 2: Взвешенное среднее (наше решение)**
```
Итог = w₁ × Предсказание_1 + w₂ × Предсказание_2 + w₃ × Предсказание_3 + w₄ × Предсказание_4
```
где веса зависят от качества модели: чем лучше модель, тем больше её вес.

**Как считаем веса:**
1. Смотрим на OOF AUC каждой модели (насколько хорошо она предсказывала на валидации)
2. Нормируем, чтобы сумма весов = 1

Пример:
- LGB-1: AUC = 0.813 → вес = 0.248 (24.8%)
- LGB-2: AUC = 0.820 → вес = 0.250 (25.0%)
- LGB-3: AUC = 0.822 → вес = 0.251 (25.1%) ← лучшая модель
- LGB-4: AUC = 0.817 → вес = 0.249 (24.9%)

**Аналогия:** Представьте, что вы спрашиваете 4 экспертов о погоде завтра. Один из них — профессиональный метеоролог (AUC=0.822), другой — любитель (AUC=0.813). Вы прислушаетесь к метеорологу чуть больше, но мнение всех учтёте.

---

### 🔬 С точки зрения ML/математики

**Формально:**
```
Для каждого таргета t и клиента i:

1. Веса моделей:
   AUC_m = roc_auc_score(y_train^(t), OOF_m^(t))  # для модели m
   
   w_m = AUC_m / Σₖ AUC_k  # нормировка, чтобы Σ w_m = 1

2. Финальные предсказания:
   Pred_final^(t)[i] = Σₘ w_m × Pred_m^(t)[i]

3. Для 41 таргета:
   Pred_final ∈ ℝ^(n_test × 41)
```

**Зачем это нужно:**

1. **Оптимальное взвешивание (Optimal Weighting):**
   - Простое среднее предполагает, что все модели одинаково хороши
   - В реальности модели имеют разное качество
   - Веса пропорциональные AUC дают больший вклад лучшим моделям

2. **Почему OOF AUC, а не train AUC:**
   - Train AUC — завышена (модель видела эти данные)
   - OOF AUC — честная оценка (модель не видела эти данные)
   - Используем OOF, чтобы веса не были переобучены

3. **Математическое обоснование:**
   
   Если предсказания моделей — это несмещённые оценки истинной вероятности:
   ```
   E[M_m] = p_true  # математическое ожидание = истинная вероятность
   
   Тогда оптимальные веса минимизируют дисперсию:
   w* = argmin_w Var(Σ w_m × M_m)
   
   При условии некоррелированности ошибок:
   w_m ∝ 1 / Var(M_m)  # больший вес моделям с меньшей дисперсией
   
   AUC — прокси для обратной дисперсии: выше AUC → ниже дисперсия ошибок
   ```

4. **Почему не обучать веса на валидации:**
   - Можно было бы использовать линейную регрессию для обучения весов
   - Но это рискует переобучиться на конкретную валидацию
   - Простая формула w_m = AUC_m / Σ AUC — робастнее

5. **Эффект на качество:**
   - Простое среднее: Macro AUC ≈ 0.825
   - Взвешенное: Macro AUC ≈ 0.827
   - Прирост: +0.002 (на лидерборде это может быть 10-20 позиций)

## Шаг 6: Мета-признаки для сложных классов (Meta-Features for Hard Classes)

### 📖 Простыми словами

**Проблема:** Некоторые продукты очень сложно предсказать.

Например:
- `target_9_3` — AUC = 0.671 (очень плохо)
- `target_6_1` — AUC = 0.630 (ещё хуже)

Почему? Потому что для этих продуктов мало явных паттернов в данных.

**Решение:** Использовать предсказания для **других продуктов** как дополнительные признаки!

**Логика:**
- Клиенты, которые берут продукт A, часто берут и продукт B
- Например: кредитная карта → кредит наличными
- Если мы хорошо предсказываем продукт A, используем это для предсказания B

**Как делаем:**
1. Находим 9 "сложных" продуктов (AUC < 0.75)
2. Для каждого сложного продукта:
   - Находим 10 других продуктов, которые с ним коррелируют
   - Добавляем предсказания для этих 10 продуктов как новые признаки
   - Обучаем финальную модель с этими мета-признаками
   - Получаем улучшенные предсказания

### 🔬 С точки зрения ML/математики

**Формально:**
```
Для каждого "сложного" таргета t (где AUC_t < 0.75):

1. Поиск коррелирующих таргетов:
   corr(t, j) = PearsonCorrelation(y^(t), y^(j))
   
   Top10_t = top_10(|corr(t, j)|)  # 10 самых коррелирующих таргетов

2. Добавление мета-признаков:
   X_meta^(t) = [X_selected^(t) || OOF_Top10_t]
   
   где OOF_Top10_t ∈ ℝ^(n_train × 10) — OOF предсказания для топ-10 таргетов

3. Финальная модель:
   M_final_t = LGBM(n_estimators=300, lr=0.03, num_leaves=31)
   M_final_t.fit(X_meta^(t), y^(t))

4. Предсказания на тесте:
   Pred_final^(t) = M_final_t.predict([X_test_selected^(t) || Pred_Top10_t_test])
```

**Зачем это нужно:**

1. **Transfer Learning между таргетами:**
   - Таргеты не независимы: `P(y^(i), y^(j)) ≠ P(y^(i)) × P(y^(j))`
   - Корреляция между таргетами — источник дополнительной информации
   - Предсказания для одного таргета содержат информацию о других

2. **Почему именно OOF предсказания:**
   - OOF — предсказания на данных, которые модель не видела
   - Нет утечки информации (data leakage)
   - Честная оценка для использования как признака

   ```
   ❌ НЕПРАВИЛЬНО: использовать train предсказания (утечка!)
   ✅ ПРАВИЛЬНО: использовать OOF предсказания (честно)
   ```

3. **Математическая интуиция:**
   
   Если таргеты коррелируют:
   ```
   y^(t) = f(X) + g(y^(j)) + ε
   
   где g(y^(j)) — вклад других таргетов
   
   Тогда добавление предсказаний для y^(j) как признаков
   позволяет модели выучить g() и улучшить предсказания
   ```

4. **Почему только для сложных классов:**
   - Для классов с AUC > 0.75 модель уже хорошо работает
   - Добавление мета-признаков может добавить шум
   - Для классов с AUC < 0.75 риск оправдан: терять нечего

5. **Почему 10 коррелирующих таргетов:**
   - Меньше 5 — недостаточно информации
   - Больше 15 — добавляется шум и риск переобучения
   - 10 — эмпирический компромисс

6. **Эффект на качество:**
   - Для сложных классов: прирост AUC на +0.01-0.03
   - Для общего Macro AUC: прирост на +0.002-0.004

**Риски:**
- **Утечка данных:** Если использовать не-OOF предсказания
- **Переобучение:** Слишком много мета-признаков
- **Вычислительная сложность:** Нужно обучить ещё 9 моделей

**Как минимизируем:**
- Используем только OOF предсказания
- Ограничиваем 10 таргетами
- Обучаем только для 9 сложных классов
